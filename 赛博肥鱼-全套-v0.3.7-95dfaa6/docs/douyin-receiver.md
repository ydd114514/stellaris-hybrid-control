# 抖音后台只读接收器

模块：`douyin-receiver.ts`、`douyin-protocol.ts`、`douyin-signer.ts`。使用项目已有的 `ws` 与 Node 内置 crypto/zlib，不安装系统代理、证书或改声卡，不访问浏览器、QQ或其它项目的登录资料。

`createDouyinReceiver({signer,onEvent,onStatus})` 提供 `start(room)`、`stop()`、`info()`。公开 `https://live.douyin.com/数字` 按 web_rid 解析；17–20位裸数字或 `room_id:数字` 按内部uint64处理，不把内部ID误当网页号。内部ID握手时 `roomStatus=unknown`，不等同已开播。真实房号仅由用户配置保存，仓库没有默认实际房号。

服务器的真实 protobuf 帧或原生pong才更新健康时间。每5秒发ping，20秒无服务端回应才降级；安静无弹幕不算断线。解压最多4MiB、每帧最多1000条，待交付队列256，事件去重10000，有界重连3次。只有服务端稳定msgId/userId完整的消息才能成为事件；social仅明确action=1算关注，礼物保留原始单价与累计数量/连击key，由核心净增去重。未知数量/价格不臆造。

`connected` 表示 WebSocket 传输握手，收到帧/pong和真实互动另有时间戳；不能仅据本机桥连接宣称抖音接通。未开播、校验拦截、匿名标识或签名失败均明确告知并可由控制器切换画面识别，不重启主app或改变直播声音。匿名网页接收不保证平台向未登录连接下发全部礼物。

## 双路与自动发现

主程序将后台直连和已有本机事件桥作为 A 类来源，B 为指定直播助手窗口的本机读图。后台健康优先；明确断连或心跳超时后，B 接管评论，A 稳定恢复后切回。画面礼物连续确认后等待约两秒补缺，尝试与后台同份礼物合并；这是确认之后的等待，并非端到端两秒保证。切换不会向小店发送暂停、静音或停止音乐命令。

房号留空时，只检查伴侣主日志最新文件末尾的 `web_rid`、`room_id`、`roomID` 公共数字字段，保留字符串，不提取其他字段或登录凭据。优先网页号，超过十二小时的旧日志不自动选用；手填房号优先。发现值仅在内存中作为候选，最终活动状态与连接健康由接收器判断，不能把发现房号当成已开播。

B 使用零缩略图窗口列表选择目标，再由 ScreenCaptureKit 精确取该窗口的两块区域送本机 Vision；不采整屏、声音或其他应用画面。录屏权限需用户手动允许。评论/关注至少两帧一致、礼物至少三帧一致，保留原始识别置信度；纯白、纯黑或透明画面按失败处理。画面行 ID 不是平台事件或用户 ID，同名、滚动、布局变化及消息过快消失可能造成漏识或关联误差，去重只能尽力而为。屏幕观察独立于模拟、本机接入与未知来源，不提供可信价格、收入或换装资格。

开播前需确认当前窗口、区域、权限及接收设置；窗口重新创建后 ID 可能改变。开播后保持现场不刷新、不重启、不手动调整，异常记录后留待下播处理，由预设主备机制继续工作。

## 已验证范围

真实预检建立了后台传输握手，并收到服务端帧和心跳，但没有收到真实观众互动，内部房间活动状态仍未知。真实直播助手裁图能显示评论、礼物面板与占位说明，未把占位文字解析成事件；这证明取图有效，不证明真实弹幕或礼物链路已通。先前将纯白裁图视为空消息区的结论已撤回，截图缩放修复后重新核对了真实内容。

协议字段、累计连击、跨路去重和多帧候选已用离线样本验证。尚未完成真实开播后的观众评论、礼物完整性、跨路切换及平台最终接收端音画验证，不能承诺所有礼物可见或永不漏重。

## 签名源码与授权边界

优先从公开房间HTML发现官方SDK地址（官方域名白名单），源码仅存RAM。隔离隐藏Renderer使用全新内存session、sandbox、无Node/IPC桥；cookie固定为空、storage仅内存，全部对外网络和权限被禁止。脚本的字节码运行需要隔离Renderer中的 `unsafe-eval`，它不具备主进程或用户资料权限。签名摘要/结果、匿名cookie从不进入状态或日志。

`createDouyinSigner` 模块默认不启用固定备用；当前主程序显式传入 `allowPinnedFallback:true`，优先尝试公开房间中的官方SDK地址，失败时可从下列固定公开源码URL取RAM备用。因此当前应用并非只依赖官方SDK下载路径：

- 来源仓库：[qinant/dycast-desktop](https://github.com/qinant/dycast-desktop)，审阅提交 `43bf564c2d0c540ec912648deecc4946af5e87d1`，仓库根LICENSE为MIT。
- 备用脚本：[该提交 public/mssdk.js](https://raw.githubusercontent.com/qinant/dycast-desktop/43bf564c2d0c540ec912648deecc4946af5e87d1/public/mssdk.js)，约323KiB，平台SDK没有单独明确的授权声明；仓库MIT不能自动证明平台SDK原作者另行授权。
- 未把SDK静态vendor提交或打包，没有外部收费签名服务。需要分发离线SDK时，应先单独核对授权。构建不拷贝开发审阅缓存；当前主程序先尝试官方公开SDK，必要时使用上述固定源码备用，源码仅存RAM。
- 协议字段对照该仓库 `src/core/model/`；本项目的有界wire reader为独立实现，未复制/执行其完整app。

原项目 [v1.4.1](https://github.com/qinant/dycast-desktop/releases/tag/v1.4.1) 发布元数据含 `Dycast.Desktop_1.4.1_aarch64.dmg`。其生产Rust层直连HTTP/WS；文档中的代理用于浏览器开发环境，并非必须安装系统代理。本文不等于对本机目标房间已连接成功的声明。
