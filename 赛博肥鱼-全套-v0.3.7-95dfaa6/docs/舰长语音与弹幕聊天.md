## 使用流程

1. 打开桌面端“舰长语音与聊天”。
2. 在B站直播页连接真实房间，在AI中枢配置场控模型。可以先点击“启动弹幕文字回复”，无需选择声音或填写语音密钥。这里与AI中枢共用运行状态；“停止AI中枢”会同时停止场控与参谋，游戏控制器独立运行。
3. 新建全量版资料默认采用最后的“呆萌平常话”；旧资料可点击“使用已调好的角色声”切到revision 4和北京接口。该操作保留已有加密密钥、清空原业务空间ID，语音仍保持关闭。推荐小样与参数见下文。
4. 若继续排查原fishcute3定制音色，保存对应账号的API Key、百炼接口地址和业务空间ID，再点击“查询已保存设置的音色状态”。密钥经Windows安全存储加密，不出现在网页、日志或子进程参数中。一次点击只发一次查询，停止可取消，迟到结果不会恢复状态。资料需要匹配所选音色、目标模型及OK状态；失败或缺失显示未知。`AllocationQuota.FreeTierOnly`不能推出整个TTS服务不可用，资料查询通过仍不等于合成成功。公开推荐音色不调用该定制音色查询接口。
5. 原fishcute3的20版试听仍可独立使用：实际生成并核验后，打开试听页对比并点击“确认使用”。推荐版可直接采用，无需等待原20版。文件必须匹配模型、音色、语速、台词、表达指令和SHA256，且是完整、有有效音量及时长的PCM WAV。仅有ready标记、损坏文件或手填presetId不能启动语音。采用推荐版或确认试听只保存配置，语音仍保持关闭。
6. 点击“启动语音与聊天”会在勾选“朗读弹幕回复”时核对场控是否启用、服务商、模型及可解密密钥，再启动尚未运行的AI中枢；未配置好则停止语音并提示。仅朗读游戏打算时不自动启动聊天模型。用户独立启动的文字聊天不会被停止语音顺带关闭。
7. 浏览器源使用`http://127.0.0.1:17655/overlay?voice=1`，启用浏览器源音频。新版OBS导出已包含该参数和音频路由；已有场景需要手动更新来源地址。升级0.3.12后，自行重开新版并准备直播画面、刷新OBS来源，主字幕与独立`/host`页才使用实际播放状态；未开口不显示后台生成文本。
8. 直接本机试听时点击“打开本机语音播放器”；交给OBS送音时关闭本机播放器，同一时刻仅一个播放器持有租约，约5秒后可切换。没有播放器在线时不发起配音请求。

网页预览默认静音，只有点击“试听直播语音”才接入播放器。整个模块不设置推流、不启动正式直播，不自动运行游戏。

## 语音链路与成本控制

`实时游戏日志的公开intent.explanation → 有界队列 → 千问TTS → 本机播放器 → 直播软件浏览器源音频`。

`真实B站弹幕 → 既有场控编排 → 当前局背景 + 有界黑板 → 公开回复 → 同一语音队列`。

不读取DSH内部thinking、reasoning或完整推演。重新启动从当前日志尾开始，不重播历史意图。队列最多8条，旧游戏计划只保留最新一条；观众回复优先，超过30秒丢弃。同一段游戏打算60秒内去重。合成和播放串行，有实际播放器连接才产生配音请求；同一时刻仅一个播放器取得输出租约，避免多个浏览器源重复播报。

默认每小时240次配音上限，可在后台降低。连续3次合成失败停止语音，需要人工确认修复后重启，不持续烧请求。合成失败仍保留服务端已报告的用量；未报告用量不补造计费数字。文本模型沿用AI中枢的请求预算与缓存规则，语音合成不再调用文本模型改写。

停止立即取消在途合成、清空队列并让播放器停音，迟到回调不能复活旧语音；关闭桌面端也执行清理。停止语音只停止本模块顺带启动的场控，不关闭原本已由用户独立启动的场控。
