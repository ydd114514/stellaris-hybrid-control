# B站群星直播 · 本地接入版 0.2.0

最新用户要求：取消配音，仅保留思考字幕。框面服务已不再合成或播放语音，旧voice=1参数也无效。新导出OBS场景的框面为纯字幕；下文涉及解说音频的历史说明不再适用，游戏本身声音仍由直播软件采集。

打开桌面的“大肥鱼 DSH”，进入“B 站直播”。本版本准备直播画面、OBS 场景和本地弹幕入口；不登录 B 站、不获取推流密钥、不自动开播。用户当前没有开放平台项目，真实 B 站弹幕来源与账号推流尚未联调，不能把本机监听成功当成已经连接直播间。

## 画面

点击“准备直播画面”，再“打开静音预览”。预览为最近实机截图；正式视频使用 OBS / 直播姬的实时游戏采集，不能把该低频预览录成游戏直播。

OBS：点击“导出 OBS 场景”，在 OBS“场景集合 → 导入”中载入 JSON。已另放一份在`E:\肥鱼直播\直播素材\大肥鱼群星-OBS.json`。画布为1920×1080，两层从下到上：

1. `game_capture`，匹配 stellaris.exe，边界 X32、Y78、1504×846，包含游戏声音。若第一次未匹配，在该来源属性中重新选择实际 Stellaris 窗口。
2. `browser_source`，`http://127.0.0.1:17655/overlay?voice=1`，1920×1080、透明游戏孔、右侧弹幕与航行记事、下方简短解说。已开启浏览器源音频重定向到OBS。

场景没有加入整屏采集、麦克风、桌面音频或账号配置。游戏音量默认0.6、解说1.0；导入后仍需检查实际音量。不要另外重复采集同一份游戏/解说声音。

右侧角色卡底部有小型“API余额”面板，只显示DeepSeek官方余额接口返回的剩余金额，每5分钟刷新；密钥只留后端，不用模型生成或估算余额。已打开的框面刷新一次可加载该增量。

有账号第三方推流权限时，在自己的 B 站账号和 OBS 中配置；是否有该权限以账号当前页面为准。没有时可用直播姬。直播姬若提供网页/浏览器素材，可按同样位置添加游戏采集并在上层叠加框面；该客户端版本的网页素材和音频选项需按实际界面核对，尚未实机验收。也可用 OBS 虚拟摄像机传入直播姬，但虚拟摄像机只传视频，不能因此认定解说有声。声音需单独采集或走用户选择的专用音频通道；本版本不安装虚拟声卡、不改系统默认声卡、不自动开启音频监听。

先本地录一小段，确认实时游戏、字幕、角色、记事、游戏声和解说声齐全且无回声，再由用户手动开播。

## 本地弹幕

点击“开启本地弹幕接入”，再“复制接入配置”，交给已授权的本地弹幕转发工具。只监听127.0.0.1，支持带令牌的HTTP POST和WebSocket。端口默认17658，占用时自动选择空闲端口，必须以新复制的配置为准。

配置中的Bearer令牌与WebSocket带令牌地址仅进入用户主动复制的剪贴板，不出现在公开状态、直播框面或普通日志。JSON数据格式沿用项目已测试的规范化事件协议：

```json
{"id":"平台消息唯一ID","platform":"bilibili","kind":"chat","user":{"id":"观众ID","name":"观众昵称"},"text":"真实弹幕内容","at":1793090000000}
```

接收器会鉴权、校验平台、按消息ID去重后写入当前群星工程的`.local/commentary/audience.jsonl`，框面从文件读取并用文本显示。观众文本不会作为游戏、Shell或模型指令执行。本地接口不是B站弹幕抓取器；当前只负责聊天上屏，自动弹幕回答、点歌和真实平台来源仍待后续接入。

“测试本地接入”只走回环HTTP、鉴权和解析，不注入假弹幕、不调用模型。关闭桌面端会关闭它开启的本地弹幕接收器，游戏由群星控制页单独管理。

## 验证

新增服务4项、现有控制器9项、桌面E2E3项，以及源码/打包Electron隔离冒烟通过。`scripts/verify-bilibili-local.mjs`在独立临时目录和随机端口实测HTTP→JSONL→解说服务→浏览器框面，验证第一条消息、去重、测试不注入、透明孔及1920×1080尺寸；没有接触真实用户资料、游戏、B站或API。导出的OBS源类型及音画设置已按本机OBS32.2.2和官方实现核对；尚未声称OBS/直播姬实际推流或音频全链路验收通过。
