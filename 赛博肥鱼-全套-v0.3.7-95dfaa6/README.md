# 赛博肥鱼 · 全天小店

新增“大肥鱼 DSH”Windows桌面控制台：双击打开大肥鱼DSH-Windows.bat，直接手动启停群星控制器、查看状态。打开软件不会启动游戏；运行引擎是官方DSH，控制台由本项目提供。详见[桌面端说明](docs/DSH桌面端.md)。

Windows / Mac 上的 AI 小店直播工作台。沿用 Coopanion 的 DeepSeek 大肥鱼，提供专用竖屏采集窗口、独立直播音频、本地监听、弹幕互动和有秩序的点歌台。

**Windows 用户先看 [Windows直播使用说明](Windows直播使用说明.md)**：双击 `启动小店-Windows.bat` 可运行，安装包位于 `release`；Windows 使用 VB-CABLE，输出为 CABLE Input、伴侣麦克风为 CABLE Output。下文原有 BlackHole 与钥匙串说明属于 macOS。

## 打开和试用

打开 `release/v0.3.2/赛博肥鱼.app`，或安装 `release/赛博肥鱼-0.3.2-arm64.dmg`。也可以双击项目里的 `启动小店.command`。当前为 Apple Silicon 本地开发签名版本。

首次建议点「独立本地测试」，也可以双击 `启动本地测试.command`。测试窗口使用 `.local/test-data`，强制模拟回复，关闭真实输入桥，不使用直播密钥或虚拟声卡。默认监听关闭，排练不会在电脑上发声。打开「本地监听」后可免费试听系统语音。

主工作台的「开始营业」只启动小店；真实抖音开播由你在直播伴侣中操作。AI 默认自动接话，也可逐句人工确认。**⌘ Enter** 通过草稿，**Esc** 打断发言。

## 全天场景

默认按这台电脑的真实日期、时间和时区变化：06:00–10:00 为晨光小店，10:00–17:00 为日间小店，17:00–20:00 为黄昏小店，其余时间为深夜小店。窗外天色、太阳/月亮、招牌、菜单和介绍会一起变化；雨雪等布景和角色配色保留。店长自定义的店名不会被覆盖。

「形象与动作」可手动预览四个时段，再选「跟随真实时间」恢复自动。手动布景不修改电脑时钟。AI 每次收到真实时间和布景信息，不会把白天当深夜，也不会把虚拟雨景当成真实天气。自动跨时段不重开窗口，不中断当前配音或点歌。

## 对接抖音直播伴侣

### 画面

「直播连接」→「打开专用采集窗口」。窗口标题固定为 **赛博肥鱼 · 抖音直播采集（9:16）**，画面不含后台控制按钮。在直播伴侣添加「窗口」素材并选择它；本地测试窗口标题不同，避免选错。

本机已在直播伴侣「场景四」添加该窗口，并用「等比缩放」铺满竖屏预览。这里只完成预览配置，没有点击直播伴侣的「开始直播」。

默认内容大小 540×960 点，在 Retina 屏对应 1080×1920 像素。窗口可放在其他应用后面；避免最小化或隐藏正在采集的窗口，直播伴侣对被隐藏窗口的行为需实际确认。后台控制窗口关闭后收进菜单栏，营业继续；菜单栏有显式「退出小店」。

### 直播声音与本地监听

1. 安装官方 **BlackHole 2ch**，按安装器要求完成系统授权。当前这台 Mac 已安装。
2. 小店「直播连接」选择 **直播模式**，直播专用输出选 **BlackHole 2ch**。千问配音和歌曲进入同一个小店混音通道；说话时自动压低音乐。
3. 直播伴侣设置：**麦克风 = BlackHole 2ch、输入音量 100%；系统扬声器采集音量 0；音频监听 = 仅输出（不监听）**。本机已按此配置。这样日常工作声音不会跟着系统扬声器被采进去。
4. 要调试听感，打开小店「本地监听」，选择电脑扬声器或耳机。关闭监听只停止这条本地通道，直播输出保持；不改 macOS 的默认输入或输出。
5. 直播模式禁止系统朗读，以免它绕过专用输出。请配置千问，或暂时使用文字表演。设备断开时停止该直播音频通道，避免落到默认扬声器。

监听的是本项目直播混音的独立分路；它不是对直播平台最终编码/网络传输的回听。最后仍应在直播伴侣预览和实际接收端检查音画同步。

### 互动数据

画面与声音采集不等于弹幕数据连接。「直播连接」提供两路接收：**A 后台事件**匿名连接公开直播间；**B 直播助手画面**只在本机读取选定窗口的评论、礼物区域。后台优先，明确断连或心跳超时后由画面接管评论，后台稳定恢复后切回；匿名后台可能遗漏的礼物由画面多帧确认后延迟补缺。切换只改变消息来源，不暂停小店、配音或音乐。

A 可手填房号；留空时只从伴侣最新主日志发现公共数字房号，不读取登录凭据或推流资料、不持久保存发现值。发现的房号只是候选，旧房号与传输握手都不能证明当前已经开播或收到互动。B 需要手动允许录屏，开播前选好当前窗口、核对两张裁图并保存；不读取整屏、排行榜或声音。纯白、纯黑或透明画面判为读取失败，低置信与不完整昵称不猜认。

macOS 可能把主程序和内置 `live-screen-ocr` 作为两个录屏授权对象。主程序能列出窗口不代表组件已获准；若实际裁图仍报权限错误，可在系统录屏设置中由用户添加应用包内 `Contents/Resources/app.asar.unpacked/dist/electron/native/live-screen-ocr`。不自动修改系统授权；以实际裁图成功和连续读帧为准。

画面评论至少连续两帧一致，礼物至少三帧；确认后还有礼物补缺等待，因此不能保证两秒内接收。画面没有平台稳定用户或事件 ID，滚动、同名、布局变化和快速消失的消息可能造成漏识或关联误差，跨路去重也不能保证覆盖所有情况。画面礼物不作为真实价格、平台收入或换装资格凭据。详见 [后台接收器与验证边界](docs/douyin-receiver.md)。

已有弹幕工具仍可接入 **仅本机 HTTP / WebSocket 输入桥**。「直播连接」可启动桥、复制接入参数、轮换令牌和运行不调用 AI 的接入自检。令牌不写入普通日志或全局状态。完整格式、来源限制和示例见 [直播接入参考](docs/直播接入参考.md)。

「直播连接」与「小店养成」按模拟排练、本机接入（后台直连或本机桥）、屏幕观察、来源未标明四类分别计数，并列出最近 20 笔礼物的送礼人、名称、净增数量和来源。稳定事件 ID 去重，累计连击 2→5 只再加 3 个；传输次数包含重发，不充当独立礼物数。屏幕观察独立标注，不能冒充后台核验；旧累计没有来源时不猜测归类，抖音实际到账以平台账单为准。

当前已验证真实后台传输握手与服务端帧/心跳、直播助手真实区域取图及占位文字不误报；评论、礼物解析和主备去重另有离线样本验证。尚未据此完成真实开播后的观众弹幕、礼物全链路或平台最终音画验证，不能称为“真实互动已全部接通”。开播前完成设置；开播后保持现场不刷新、不重启、不手动调整，故障先记录，由预设主备机制继续接收。

## 点歌台

### QQ 音乐

在桌面版「点歌台」的 QQ 音乐面板搜索歌名或歌手，用手机 QQ 或微信扫码登录。登录的是本项目自己的音乐连接，不读取已安装 QQ 音乐或浏览器的账号资料。QQ 音乐 App 扫码暂不支持，请选择手机 QQ 或微信。

默认开启「弹幕自动搜索 QQ 音乐」：观众发送「点歌 歌名」或「点歌 歌名 歌手」，曲库未匹配时会自动搜索并验证完整音源，可播就直接入队，无需店长确认或预先选歌。搜索结果也可由店长手动加入曲库或队列。歌曲进入与配音相同的 BlackHole 混音通道，本地监听、紧急静音、讲话压低音乐继续有效。

本接入使用社区维护的非官方 QQ 音乐适配器，完整播放取决于账号、曲目和地域权限；搜索到不等于可以完整播放。不能取得完整音源时会跳过，不用试听片段冒充整首。登录失效需重新扫码。登录会话由系统安全存储加密，临时音源链接不进入曲库、日志或舞台状态。退出登录会停止当前 QQ 曲目并取消在途请求。

### 自有曲库与共同规则

先导入你有权播放的本地歌曲，或由店长添加可直接播放的 HTTPS 音频。导入文件复制到项目数据目录，曲库重启保留。

- 观众发 **点歌 歌名**，优先匹配曲库，未匹配时自动搜索 QQ；只加入队列，当前观众歌曲继续播放。网络搜索串行处理，同时最多保留 4 条待搜索请求，超时或取消不会迟到插播。
- 点歌后送出的 **小心心**计入本人这一轮待播优先值，多的先播，同数先来先播。真正开始播放的回执才消费清零，下一次点歌重新计算。事件重发、累计连击和点赞不会多算；取消或失败尚未播出的计数保留到本人下次点歌。本轮请求和优先值不跨应用重启保留。
- 默认每人最多一首待播、个人冷却 180 秒、全场请求间隔 3 秒、队列最多 20 首。
- 本地曲库可设所有观众、仅熟客或人工审批；可播 QQ 歌曲直接排队，仍遵守冷却、屏蔽及队列限制。
- 发 **切歌** 只投一票。默认从真正开始播放起听满 45 秒，再同时满足至少 3 位独立观众、60% 活跃观众同意才切换。缓冲时间不算播放时间，重复刷屏不增加票数。
- 店长可直接播放、编排多首、暂停、切歌和停止。暂停恢复不从头播，过期播放回执不能切掉下一首。
- 发 **取消点歌** 只取消自己的待播申请。点歌走本地命令，不消耗对话模型 tokens。

### 无人点歌时的 QQ BGM

默认按你提供的顺序循环 QQ 背景歌单：《望むのは日常》—近藤佑輔、《Killer（杀手）》—菅野祐悟、《プレパララ》—アリスソフト、《ENDLESS ENGRAVE》—深爪貴族。在点歌设置里可以从曲库勾选、调整顺序并保存，也可关闭 BGM。

BGM 不占观众队列，也不消耗观众的本轮小心心。有待搜索、待播或正在播放的观众点歌时，BGM 停止；全部点歌处理完、队列清空才恢复。两者始终使用同一条播放器与直播混音输出，讲话时压低、暂停或静音时停止。QQ 无权限或登录失效会明确提示；失败曲目挂起，全失败后不反复请求，不以试听或其他音乐冒充所选曲目。

## 更自然的互动

保留 Claude 主线新增的长期熟客记忆、聊天档案、明日计划投票、换装/场景与 token 钱包，并修复了桌面命令未登记的问题。本次增加礼物回应给普通聊天让位、刷屏合并与每人待回复上限、过期消息处理、屏蔽观众完整拦截、点歌状态反馈。交互机制参考 AI-Vtuber、AIRI 和 Open-LLM-VTuber 的原仓设计，未复制它们的代码。

采集画面的柜台前展示观众昵称、原话和肥鱼回复组成的聊天记录，保留口粮小底栏。点歌信息放在店名下的细横条，投票面板自动让位，不盖住菜单招牌。玩法改由肥鱼在暖场时用小店长揽客的口吻说，一两句教一个操作；每五分钟最多一条，有客人发言时先接客人，不打断聊天。有人问「怎么点歌」「怎么养你」「灯牌有什么用」，肥鱼会直接用预设台词回答并经过当前配音通道，不为说明操作额外调用对话模型。这些规则同时进入默认人设及固定互动提示，旧的自定义人设仍保留；普通回答不逐句催关注或礼物。

给具体观众的回复先自然点名；模型漏掉时由程序补齐，并同步到配音、字幕和聊天记录。口头称呼去掉模拟标记与装饰表情，过长、链接或不适合朗读的昵称改为「这位朋友」，原昵称和稳定身份仍用于独立聊天记录，不会把同名观众合并。

**AI 皮套梗**：本体是 DeepSeek 大肥鱼。形象页明确列出 DeepSeek 原版蓝、DeepSeek Harness 纯黑、ChatGPT 银白、Claude 赤陶、Gemini 四色、千问紫、Kimi 黑蓝、MiniMax 玫红橙，三套服装独立切换。对话会收到当前扮演身份，知道自己此刻在装谁；换皮不会改变实际对话服务。观众明确提议换装时，必须已有系统记录的关注与真实礼物，经过三轮间隔拉扯才可能同意；重复刷屏、口头声称和同名别人的记录不算。换好后全场与本人均有冷却，店长手动切换不受观众资格限制。

**本场心情与聊天节奏**：热闹、舒缓、坐不住、安静和来客时的开心，按最近收到的互动变化，不把它当作真实在线人数。无人打断时主动聊天优先延续最近的公开话题；普通聊天跟随观众具体内容，不反复递茶、热水或安排座位。后台展示当前心情，店长可设置主动语音间隔和上限；动作与 QQ BGM 衔接空档。

冷场小剧场默认开启：店猫招聘、肥鱼演技课、虚拟老板椅争夺战、尾巴音乐比赛和便签创业各分四段，按开场、添乱、自己接梗、收尾邀聊推进，真实播放完成后才进下一段。公开话题未结束时优先继续原话题，超过六分钟没有新补充则转入节目，不被一条旧弹幕永久占住；没有公开话题时，小剧场交替用 AI 演绎和本地台词，AI失败或超时可在同一额度用本地剧情接住，不循环重试。只使用现有动作与表情，不实际换装或操作电脑。

主动发声至少间隔 120 秒、每小时最多 24 轮，默认按额度均匀分配为约每 150 秒一段，避免先耗尽额度再长时间沉默。DeepSeek 闲聊、预设配音和暖场共用额度，小时账会保存，重启或新客出现不抹账；普通观众回复不占主动额度，但仍受总预算、排队和反刷屏控制。普通进场不掐断节目、不重置冷场计时，真正弹幕与礼物优先于欢迎和节目。可关闭小剧场恢复慢节奏，设 0 关闭主动语音并保留免费动作和文字。旧版整套默认120秒/12轮/300秒自动升级，自定义限额和关闭开关保留。

**token 口粮**是跨场次保留的玩法余额，初始 100,000。默认小心心 +2,000、热咖啡 +20,000、小星星 +10,000、小灯笼 +40,000，店长可在礼物规则修改；礼物名与 ID 需对应实际输入来源，平台灯牌没有匹配规则时不会冒充已补粮。DeepSeek 与千问返回真实输入/输出 token 后一次扣除，失败或取消已返回的部分照记，缺失部分标待核算，字符不换算 token。画面显示余额与最近增减，不做每秒伪造扣数。店长可补给或重置口粮；重置本场费用不会抹掉口粮余额。

口粮与元钱包、平台收入、服务商余额相互独立。模拟礼物会在隔离排练里演示补粮，后台按来源标注；聊天里口头声称送礼不会增加余额。直接聊天、点歌、关注都能陪肥鱼开店；灯牌与礼物自愿，不换取优先回应或强制切歌。

千问遇到没有返回音频或用量的临时服务错误时，最多延迟重试一次；每次真实请求各自记次数，失败未知费用继续待核算。鉴权、模型业务错误、限流、已返回音频或用量以及取消不自动重试。暂停、静音或结束会取消等待及在途配音，迟到结果不能恢复播放。

直播配音走内存 PCM 或远端音频流，不逐句生成本地语音文件；音频数据不进入运行状态持久化、聊天历史和导出日志。播放结束、打断、暂停、切换及退出会停止播放器并释放音频节点、缓冲和引用，取消后迟到的数据不能创建新播放器。为比较音色而显式生成的 `.local/voice-auditions` 样音独立保留，不属于直播缓存。

## 真实 AI 与费用

在「设置」保存对话服务和千问密钥，核对模型/接口/地域/音色，再测试。关闭模拟模式后才使用真实 AI。密钥由 macOS 安全存储加密，本地测试窗口不会读取它们。

要比较音色，可以显式运行 `node scripts/voice-auditions.mjs --generate --workspace <北京业务空间ID>`：用本项目已保存的千问密钥生成 10 段同文样音，覆盖 3.0 Flash、3.1 Flash 与 3.1 Plus，保存在 `.local/voice-auditions`。这会产生真实配音用量，每批最多 12 次、无自动重试；不带 `--generate` 只显示计划，不读取密钥或调用 API。它不修改当前直播音色或配置。

「开播」和「设置 → 电费预算」均显示两家实际网络调用、成功/失败/取消次数，以及服务端返回的输入、输出和缓存 token。未发到服务端的本地取消不计请求；旧记录缺失、失败或中断时没有返回的用量明确标记为未知，字符数不会冒充 token。导出日志包含这些计数。

在「电费预算」填写实际单价和预算。单价为 0 时只记录用量，预算无法准确限制实际费用；估算与最终账单以服务商为准。千问 3.1 Flash 按输入/输出音频 token 估价，字符计费模型单独使用服务端计费字符。连接测试和试听会产生真实服务用量；自动测试全部离线、不调用付费 API。

`node scripts/live-rehearsal.mjs` 只显示计划。显式加 `--run-real` 才会只读本项目凭据，进行限时、限调用数的真实联调，并在 `.local/live-rehearsals` 留存逐次用量和报告。测试声音从 BlackHole 实际输入回听到 Mac 扬声器；主小店会暂停让出声音，测试结束后等待手动恢复，防止两个小店一起响。它关闭真实抖音输入，模拟礼物不代表平台收入。

可加 `--interactive` 根据实际回复编排观众；`--enable-warmup` 测暖场，`--enable-ai-chatter` 显式允许主动 DeepSeek 话题接续，均遵循主动语音额度与本轮调用上限。默认不启用主动 AI 闲聊，未加 `--run-real` 的任何组合都只打印计划、不读凭据。测试后台允许预览换皮、服装和布景，服务、预算与音频设置保持本轮锁定值。

千问音频解析 SSE、PCM、时间戳和用量，目前仍收齐一句音频后播放。PCM 振幅驱动嘴型，有时间戳时逐字推进字幕。

## 目录与后台运行

从本项目运行时，设置、数据库、歌库、缓存和日志放在 **项目目录/.local/user-data**。独立排练放在 **.local/test-data**。首次升级可只读迁移本应用旧配置，原数据不覆盖。测试使用临时目录。

若将应用移出项目安装到「应用程序」，可用 `CYBER_FISH_HOME` 指定项目目录；找不到项目时使用「文稿/赛博肥鱼」作为自己的运行目录。macOS 钥匙串和虚拟声卡驱动属于系统组件，无法放进普通项目文件夹。

采集舞台限制 30 帧，后台预览 15 帧，后台收起后进一步降低预览刷新。本应用不改系统睡眠、默认声卡、代理或证书；但电脑仍需保持运行才能持续直播，CPU/GPU 与网络也会有正常占用。

需要 Node.js 22.18+ 或 24+、pnpm 11.25.0。

```sh
node scripts/setup-assets.mjs  # 首次克隆：恢复用户指定的本机占位贴图

pnpm package                  # Apple Silicon DMG
```
