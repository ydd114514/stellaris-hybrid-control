# 游戏状态增量 merge-v2

只改变发送给模型的数据表示，不改变原生状态、正常引擎命令、合法性校验、journal、检查点或公开直播数据。完整状态仍保存在本地，模型每6次响应自动收到一份全量，主动observe和压缩后observe也收到全量。

`view=full`时除view标记外全部字段是当前完整状态。

`view=delta, protocol=merge-v2`时：

- 顶层snapshotId/date/remainingSeconds/paused/speed始终是当前值。
- changes按对象层级递归合并；没有出现的字段保持旧值。
- 数组整段替换，不按ID猜元素对应、不按下标局部拼接。
- null、false、0和[]都是实际新值，不可当缺省。
- removed为明确删除的字段路径数组，逐条从旧状态移除。

例如仅合金库存变化时`changes.resources.alloys.stockpile=101`，旧max和net保持；`removed=[["resources","energy","max"]]`才表示能量上限字段被删。候选、ID和战争事件的真实性仍来自本轮游戏查询，协议不授权猜测或重放命令。

`restoreModelView`是离线回放验证器。`scripts/compare-model-view.mjs`用同样真实状态、同样每6次全量频率比较旧顶层delta和递归delta，逐帧严格断言完整可还原。报告只说JSON字节，不能冒充模型token或账单比例。

`scripts/compare-native-efficiency.mjs 360`读取上一轮和本轮DSH的服务端usage及本机journal，按前6分钟窗口比较。通过snapshotId/相同inspect结果把无时间戳的DSH tool_result对齐到本机时间；无法对齐的错误返回沿用最近时间，因此窗口边缘可能存在秒级偏差，报告保留对齐计数。两轮局势与任务不同，是顺序短测，不是相同存档重放的受控A/B实验，不承诺同等长期节省比例。重要质量指标是未知执行结果、实际多类经营回读、中央事件恢复和正常画面，不能只看日期增长。
