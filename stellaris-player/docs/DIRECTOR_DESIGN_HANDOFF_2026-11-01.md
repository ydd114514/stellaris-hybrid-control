# 直播导播：当前设计、实现与 Claude 接手说明

日期：2026-11-01（北京时间）  
源码基线：`b310d24`，仓库 `ydd114514/stellaris-hybrid-control` 的 `main`。  
本说明只交接当前方案；项目方向仍以根目录实施计划 v1.5 及用户最新要求为准。

## 先读：用户当前要求

1. 原生国家 AI 持续运营帝国，大肥鱼负责战略和关键决定，导播负责让观众看懂进展。
2. 用户认为初版导播不智能，长时间反复展示同一艘科研船；此问题必须改善，不能靠增加随机切屏掩盖。
3. 自动导播每两分钟至少展示一次**完整银河星图**，约停留 15 秒。局部星系、舰船镜头、关闭面板、仅有地图数据都不算。
4. **已撤回额外重启/读档请求。** 不依赖实机的改动要集中完成；等用户下次正常开游戏再统一验收，不要读到旧交接里的“待重启”就再次催用户。
5. 不操控桌面、键鼠或窗口焦点，不自动重启/读档、不热替换 DLL、不发起付费模型请求。展示使用游戏内原生接口。

## 1. 要解决的问题和分工

旧展示逻辑挂在模型逐条下订单的路径上。原生 AI 接管后，日常工作不再经过该路径，画面就容易长时间停在同一处。导播因此被做成独立的本地展示层。

```text
原生国家 AI ── 日常经营、研究、建设、探索、调兵
      │
      ├─ 命令类别增量、帝国摘要、真实目标/队列查询
      ▼
本地导播 ── 待展示题材 → 去重/节奏 → 游戏内面板与相机 → 事实字幕
      ▲
大肥鱼模型 ── 低频战略方针与关键决定（不逐镜头调用）
```

当前实现是**规则驱动的自动导播**，不是已经具备画面理解、自动剪辑和叙事推理的视觉导演。它可以选择展示什么，但尚未证明具有成熟的直播叙事质量。

导播不能下建设/研究/舰队经营订单，不能为了展示暂停游戏或关闭原生 AI。展示失败只影响展示；停止、控制权变化和世界身份检查仍由原控制链路负责。

## 2. 当前选景策略

| 线索 | 画面 | 使用的信息与限制 |
| --- | --- | --- |
| 首次开启或完整星图到期 | 银河视图，解除跟随、居中、全图缩放 | 原生相机字段回读是必要条件；实际完整可读性尚待视觉验收 |
| 科研命令增量 | 科研面板 | 命令计数只作题材线索，不是研究已完成的证据 |
| 建设/殖民命令增量 | 自有殖民地镜头＋建设队列字幕 | 重新读取该星球真实队列；目前不自动打开星球建设详情页 |
| 资源站建设增量 | 建造船镜头 | 与科研船分开选目标，不再全部归为“探索” |
| 调查/异常研究增量 | 科研船镜头 | 按最近展示时间选目标，同一舰船有冷却 |
| 市场、传统、议程、领袖变化 | 对应面板 | 展示当前界面；不声称收益或结果已经兑现 |
| 已处于战争 | 主力镜头 | 战争存在不是正在交战的证明，字幕只说明战时主力位置 |
| 没有适合的新事件 | 科研、殖民地、舰队、政府、市场、传统概览 | 使用轮转游标，不按墙钟取余随机落点；同类有冷却 |

多个类别同时变化时都进入待展示集合，不能因为高优先级类别被展示就丢掉其余类别。新委派的计数会重置，但不重置已运行的星图回访时钟。

旧版霸屏原因：空闲选景按时间取余，调用节奏可能反复命中同一类别；探索又优先选第一艘科研船；连续 if/else 消耗了其他类别变化。上述机制已替换，但新版长期观感尚未实机验收。

## 3. 节奏与控制规则

所有时间常量集中在 `stellaris-player/src/director-settings.mjs` 的 `DIRECTOR_TIMING`：

| 规则 | 当前值 |
| --- | --- |
| 完整星图最大回访间隔 | 120 秒；提前 5 秒开始调用，为游戏线程和回读留余量 |
| 完整星图停留 | 15 秒 |
| 普通场景停留 | 18 秒 |
| 战时镜头停留 | 30 秒 |
| 普通题材冷却 | 45 秒 |
| 科研船/建造船题材冷却 | 90 秒 |
| 同一舰船目标冷却 | 180 秒 |
| 待展示题材过期 | 120 秒 |

关键处理：

- 首次成功全图后才记 `lastGalaxyAt`；普通镜头不能刷新该时钟。原生调用或相机回读失败，不记成功，按退避规则重试。
- 星图到期可越过普通场景的停留时限；中央事件和战争目标交互窗口优先，不强行关闭，解除后补展示。
- 固定模式不再自动切画面，恢复自动后若全图逾期则优先补展示。当前没有键鼠监听，也不会自动判断用户正在手动浏览哪个面板。
- 场景停留用时间戳实现，不用等待 18 秒的阻塞流程。并发 tick 防重复；展示 RPC 之间续心跳、重新检查控制权、模式及停止状态。
- 单个坏题材不能长期阻塞其他题材。无可用舰船时退回概览；失败题材冷却，全图失败按 10/20/40/80 秒退避，但仍保留“逾期”状态。
- 两分钟规则有固定/事件阻挡例外；发生阻挡或接口失败时状态必须如实显示，不能承诺画面仍严格每两分钟成功。

## 4. 完整银河接口：实现和真实状态

当前默认桥：`cyberfish-0.6.24-country-ai-galaxy-r3`。固定本机 DLL SHA256：

`7c4fdde71611edf922c4a9ae4bf7e6185c82475bc844a859e18add78324d1ddc`

固定适配 Windows Stellaris 4.5.2，不能跨游戏版本盲用。

新增游戏内接口：

- `show_galaxy_map`：关闭本程序管理的普通面板，调用底部切星图按钮使用的原生相机路径，解除跟随，进入银河模式，设置银河居中与缩放。可选 `zoom=0` 表示默认全图，或 `100..3000` 的受限缩放。
- `get_camera_state`：返回银河模式、跟随是否解除、中心、zoom、pitch、计算所需缩放及 `full_galaxy`。
- 调度器只有在切换结果和独立回读都满足条件时才重置全图时钟；较近的局部缩放不记作全图成功。

失败历史必须保留在判断中：

1. 0.6.22 的字段 `full_galaxy=true`，但实际原生渲染帧为空星空。原因包含世界坐标距离与相机 zoom 单位混用，**未通过**。
2. 0.6.23 在 1500 档显示了真实银河版图，但上下仍有裁切，**未通过完整全图**。
3. 0.6.24 默认使用原生最远 3000 档，并提供受限调整参数；已编译且必要离线测试通过，**实际完整取景仍未验收**。

因此：`full_galaxy` 目前是相机状态与取景条件的程序判断，不能代替原生渲染帧的视觉确认。不要据此把全图功能标成实机已通过，也不要未经用户要求继续改参数、催其重启。

## 5. 配置、字幕与界面

运行配置文件：控制器目录下 `.local/native-bridge/director-settings.json`，格式为 `{"version":1,"mode":"auto"}` 或 `fixed`，兼容旧的仅 mode 格式。

- 配置原子保存；损坏/无法读取时保持固定画面，避免不确定配置触发切换。文件不存在才默认自动。
- DSH 有“自动导播／固定当前画面”按钮，可在控制器运行中切换。
- 当前题材、银河回访倒计时、事件阻挡、展示失败和配置异常会进入界面；停止后不呈现自动展示仍在运行的状态。
- `director_scene` 是面向观众的事实字幕事件，进入现有字幕框面，不直接朗读原始工具日志或模型内部文本。当前 `speak:false`，不会为每镜头发起 TTS 请求。
- 字幕服务协议已升级为 `actual-playback-director-v2`，避免启动时复用不认识导播事件的旧服务。OBS 观众侧效果仍待验。

## 7. 接下来怎样推进

**先审阅并集中完成离线可做的改进，不重新开始零碎上机。** 当前离线回归覆盖持续调查噪声、同船冷却、多题材保留、全图到期抢占、固定恢复、事件阻挡、回读失败、并发/取消、退避、配置和公开状态；类型检查与 DSH 构建通过。该结果只证明相应代码逻辑，不证明实机画面或长时间直播观感。

值得优先审阅的产品缺口：

1. 从“类别变化选景”提升到围绕当前战略目标组织短叙事：目标 → 执行中的对象 → 真实进展 → 回到星图。尽量复用现有低频战略结果，不让模型逐镜头派单。
2. 命令计数只用于选景线索。需要精确讲解“刚发生了什么”时，应使用真实状态变化/队列事实，避免把 admitted 当成 executed 或 completed。
3. 现有星球接口是镜头聚焦，并非自动打开建设详情页；战时当前也只是主力位置，不能冒充自动识别精彩战斗。不要在交付描述中夸大。
4. 全图的实际边缘、可读性和 OBS 最终画面必须留待一次统一验收；程序字段曾误报，不能再仅看字段。

下次用户**正常开游戏后**，只安排一组合并检查：真实全图可读性 → 两次全图回访间隔与 15 秒停留 → 普通题材和目标去重 → 固定/恢复 → 停止暂停收权。复用已通过的原生 AI 自主经营结果，不重跑整轮，不做新的十分钟对照或长测。

本交接没有连接游戏、改动运行中的控制器或发起模型请求。
