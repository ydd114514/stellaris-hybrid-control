# 原生殖民地自动化接口核查

核查对象是本机 Stellaris.exe，SHA256 `400df27c82ddc845aa9dce79bd468d81f18f060d299cd263e3afa93aef4f7a83`。这些布局仅适用该二进制。当前默认桥为0.6.10，单星球归属/自动化关闭/队列查询已在后续住房与贸易验收中复用。原生分类写入与硬预算仍未接通；住房已采用普通建造本地调度，建筑升级本地调度已实现但未验收且默认关闭。下文0.6.8候选描述保留为历史核查记录，当前进度以实施记录顶部为准。

## 类别布局的证据链

`inspect-colony-automation-layout.py` 对精确EXE生成有界反汇编清单。输出在 `.local/hybrid-control/colony-layout-inventory/`，其中：

- `settings_vt_9.asm`：单殖民地分支在6B56A6将对象移至CColony+F00，6B56AD读取命令+30的期望布尔值，6B56B6跳入E66300；国家默认分支使用另一列表并翻转成员关系。
- `settings_apply.asm`：E66300在对象+18的指针数组中寻找类别，+24为元素数；真值仅在不存在时追加，假值仅在存在时删除。
- `automation_serialize.asm`：E64880序列化+28的总开关与+18/+24的类别列表；E64903取类别+10作为键对象；`category_key_construct.asm`中15BAF9再加10才访问字符串，即类别+20。故CColony对应偏移为F28、F18、F24。
- `automation_deserialize.asm`：E64A18通过31128C0类别数据库恢复保存的列表；相邻执行代码从自动化对象+8访问殖民地。探针要求该反向指针与已核对的殖民地地址相同。

新 `native/research/colony_settings_probe.py` 限制列表长度和字符串长度，拒绝未知键、重复键、失效指针与读期间列表变化。键还必须出现在当前本机原版类别定义中；它没有证明MOD覆盖后的有效配置，不把缺失键解释为默认启用或禁用。

仅在暂停且能核对当前玩家时运行：

```
node scripts/probe-owned-colony-automation.mjs 3 --settings
```

此命令不启用自动化、不调用游戏执行函数、不改变资源。需用户进程的只读管道和内存权限。返回的`memberKeys`仅表示序列化列表成员；`executionSemanticsVerified`与`budgetKnown`保持false。读取失败保持未知，不能降级显示为关闭。

本机原版`common/colony_automation_categories/00_categories.txt`含`planet_automation_deficit_restriction`等类别，多数定义为空、由引擎实现。类别名称和“限制赤字”不能证明具有指定金额的储备上限。接下来仍需候选查询实测、类别执行语义、单星球启停与费用/队列对账，才能决定是否接通第二类委派。

候选r2已把上述类别读取加入原生查询，独立返回`category_membership`；总开关读取不等于`settings_known`。Release编译已通过，但未加载验收，生产桥不变。完整候选与哈希见实施记录最新章节。


## 候选专用运行核对入口

`node scripts/probe-colony-candidate.mjs`默认只准备核对记录，不加载DLL。待同档对照完成并具备单独验证条件后，用户手动重启群星并载入暂停测试局，取得当前PID，再运行`node scripts/probe-colony-candidate.mjs --execute --pid 当前PID --planet-id 3`。该命令只验证候选读取，不开放建设托管。

入口固定候选r2版本与SHA256，先通过只读进程信息核对精确EXE、创建时间及已加载桥模块。未知不能当作无桥；若已有其他桥，加载器调用前就拒绝，禁止热换，不卸载或重启。仅在独立确认未加载桥时才调用既有加载器，加载器再次验证进程创建时间及EXE身份。r2哈希仅获得这条显式测试路径的加载资格，不代表实机验证通过，生产引导仍选择0.6.6/0.6.7。

候选连接只允许ping、当前状态、当前玩家、行星详情与单星球自动化读取；不能发送暂停、移动、调查、类别设置或窗口定位。要求人工保持暂停，核对有效己方行星与无效句柄的未知返回，再核对日期和进程身份不变；读取前后均须验证管道服务器确属所选PID与创建时间。成功也只是只读smoke test，不能证明启停、类别执行、实际费用或预算。

实际旧桥负例在`.local/hybrid-control/colony-candidate-1793327909970/result.json`：检测到当前0.6.7后拒绝，loaderInvoked=false、runtimeValidated=false、gameplayWrites=0。没有加载r2。模块枚举和PID复用的离线用例另行覆盖；失败不降级成“未加载”。


## 单殖民地启停命令的静态契约

`verify-colony-command-contract.py`已对精确EXE及当前SDK核对并生成`colony-layout-inventory/command-contract.json`。可复用的定义为`sdk::cmd::set_automated_development_command`：token2AFA、vtable23919F0、工厂6B9650、大小30，colony+20、country+24、range+28、enabled+2C。现有CommandBuilder能够调用引擎工厂、slot8的IsValid，再经正常PostCommand(force=false)提交，后续无需自造对象或直接写自动化字节。

执行函数6B4ED0对range分支：0走单殖民地，2遍历全部己方殖民地，1遍历后以carrier相关对象字段584筛选。范围1的“同星区”解释仍待确认，不能当作已核实语义。适配必须固定0并拒绝其他范围；IsValid核对种子对象并不足以证明批量范围符合本计划。

单殖民地分支6B50FA..6B5146最终将命令+2C写到对应殖民地F28，未调用施工取消。这意味着关闭自动化不等于撤销已进入队列的建设，也不证明已经退款；回收控制权后仍须核对在途队列与资源。已识别的这条命令字段没有金额预算，不能由此推断引擎其他位置没有预算机制。

这些是SDK复用与静态指令证据，runtimeValidated=false、apiCertified=false。候选仍只有读取接口，没有新增启停写接口，也没有动态开启建设托管。先完成候选读取运行核对，再实现正常启停提交与回读、单星球费用和在途对账。
