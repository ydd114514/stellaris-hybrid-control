# 调用消耗优化 · 2026-10-27

保持原来的DeepSeek Flash模型、正常游戏合法性校验、真实游戏画面和关键决策信息。优化重复传输与空闲轮询，不通过换弱模型或截断关键候选节省。

基线来自真实记录：`1793073150661.jsonl`共333个主模型步骤，最后一次请求携带约752705个输入token，其中绝大部分为缓存历史；本轮累计未缓存输入733542、缓存输入123178240、输出39264。这些是接口报告的用量，不能把缓存和未缓存直接当成同价账单。

已做：

1. `ModelView`传输无损的顶层变化。snapshotId和当前时间每次都发，unchanged明确沿用，removed明确删除；每6次自动给完整状态，observe随时可主动刷新。完整本地状态、执行账本和核验仍保留。同一批71个真实状态离线回放，JSON字节量585469→276832，减少53%；这不是人民币费用降幅。
2. watch在本地最多等待20秒，每秒检查中央弹窗、警报、战争、科研、舰队、外交、建设及关键资源变化。重要变化提前返回并处理中央弹窗；普通资源累加不反复唤醒模型。游戏持续正常走时间，字幕和离线语音也不产生额外模型请求。
3. 使用DSH社区原有compaction框架，替换其官方预留的summarize钩子。从本机完整游戏检查点、最近打算和失败记录生成私有记忆；保留近期对话，不调用模型做摘要。目标触发阈值为模型窗口的3.5%，近期保留8000估算token。压缩后要求先observe取新状态。关闭通用工具结果中段截断，避免损坏游戏JSON候选。

试验中曾把通用模型摘要上限设为1600，导致23次压缩尝试未完成；该轮已停止，**不能算成优化成效**。现版本是本地确定性记忆钩子，摘要不走API，需以新的持续运行记录确认正常落地和上下文下降，不只看配置。

可运行`node scripts/analyze-native-usage.mjs <事件日志>...`统计主模型步骤、缓存/未缓存/输出和上下文峰值，结果在`.local/native-bridge/usage-analysis.json`。DSH的真正压缩成败在其`.jsonl.zstd`会话内的compaction/start、summary、end事件；主控制器JSONL不包含辅助摘要调用，分析旧试验时不能漏算。

质量回归包括delta重建（0、空数组、字段删除）、周期性全量、空闲等待与科研/舰队变化唤醒、中央弹窗一秒内本地发现并暂停、原生去重和未知结果保护。当前Node270项、Python42项通过。长时间整体军事防务与通关仍在验证，不能把token变少当成游戏策略已合格。

# 不可见画面时的零模型等待（2026-10-27补充）
