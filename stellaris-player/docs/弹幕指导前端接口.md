## 接入方式

建议在现有 `/events` 状态包中增加 `audienceGuidance` 字段。现有 `render(state)` 已调用 `renderAudienceGuidance(state.audienceGuidance)`；也可以在网页同一脚本上下文调用此渲染函数。接入不需要修改 DOM 或布局。

```json
{
  "audienceGuidance": {
    "status": "ready",
    "summary": "当前可供参考的观众建议",
    "items": [
      {
        "id": "真实来源的消息或建议标识",
        "name": "观众昵称",
        "text": "后端提供的公开建议正文",
        "status": "pending"
      }
    ]
  }
}
```

上例仅说明协议，不注入正式状态。

整体状态：`disconnected` 待接入、`waiting` 等候建议、`collecting` 整理中、`ready` 有新建议、`forwarded` 已转交、`error` 暂不可用。未知或缺失状态按待接入显示。单条状态：`pending` 待参考、`forwarded` 已转交、`dismissed` 已略过；转交只表示传递建议，不代表游戏动作已执行或生效。

列表保持后端顺序、最多保留末20条。昵称最多60字，单条正文最多1000字，摘要最多200字；长内容自然换行并滚动，不用三行截断。所有字段以纯文本输出。后端需只发送可公开的摘要和建议，不能将密钥、完整内部推理或原始执行参数送入本字段。

稳定节点：`#audience-guidance`、`#guidance-status`（附 `data-status`）、`#guidance-summary`、`#guidance-empty`、`#guidance-list`。列表每10秒自动滚动，悬停和手动操作时暂停。同一状态重复推送不重建列表、不打断阅读。既有 API 余额仍在指导卡底部。
