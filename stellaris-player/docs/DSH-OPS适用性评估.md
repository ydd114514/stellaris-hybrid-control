# 用户视频与DSH-OPS适用性评估 · 2026-10-27

用户视频`https://b23.tv/WTs1VcL`实际为`https://www.bilibili.com/video/BV1Ghpy6gE5x/`。已读取作者公开简介与对应项目文档，未声称逐帧观看完整视频。B站正文有412限制，没有绕过登录。

作者简介明确：标题27倍是“Windows PowerShell下DSH标准模式”对比“dsh-ops＋DSH PTC模式”的特定示例；其中插件本身约贡献3倍。不能承诺所有工作负载省27倍或费用降为1/27。

对应MIT项目`https://github.com/T-Auto/dsh-ops`主要提供紧凑文件工具、Windows Bash、渐进工具加载，以及PTC文件/文档/批处理SDK。PTC文档`docs/native-ptc.md`明确需要宿主PTC-only模式，不会自行建立REPL、强制切换模式；在Native/both模式没有同样PTC SDK收益。文档和raw版本观察存在内容差异，若要实际安装必须固定具体发布版本及提交重新审核，不使用未固定latest直接跑安装脚本。

当前游戏profile：只暴露4个专用MCP工具observe/inspect/apply_orders/watch；Shell、文件工具、搜索、网页、子代理均禁用。因此插件用于替代这些文件/Shell工具的主体收益不直接覆盖游戏。盲装反而可能增加工具和提示前缀、引入当前玩家不需要的任意代码路径。**本轮没有安装插件、改变DSH模式或打断当前有效游戏轮。** 官方桌面客户端也没有装插件或变更账号。

只读审计当前DSH日志`1793093913837.jsonl`在277步截点：非缓存输入547500、缓存输入6959488、输出34891；输入缓存比例92.7%。这些是该文件当时的累计报告，不是费用账单，也不是独立文本体积；后续仍在运行。297个工具调用中observe2、inspect131、apply_orders106、watch58。游戏内部RPC不等于每次请求模型，不能拿原生calls7379声称API调用7379次。

工具返回正文合计约838KB（observe12694、inspect261370、apply_orders355017、watch209154字节），最多约8190字节。该游戏轮状态离线重放162份，全量JSON1083337字节、现有顶层delta523674字节，减少52%；这是字节测量，不是token或费用减少52%。本地compaction日志真实存在local_summary且modelCalls=0；旧分析脚本的compactions只数DSH公开status字段，显示0不代表本地摘要没生效。

结论：借鉴“压缩工具返回、减少错误重试与模型往返、渐进披露”的设计，但当前不值得原样安装通用文件工具插件。优化应优先游戏专用工具：减少重复嵌套状态与可复用候选、合并相关只读查询、状态无变化时本地等待、更好的合法性过滤避免反复失败；重要事件/战争保持及时唤醒。现有delta、本地摘要、合批指令已覆盖部分思想。

后续做可还原离线回放及相同时间有效经营对照，记录真实usage、缓存和成功操作，不用日期增长或体积缩小冒充节省费用。价格若计算须核对当前实际模型、时段及DeepSeek官方价格，不把缓存输入按全价计费、不把本账号余额差额直接归因本进程（同key可能其他程序同时使用）。
