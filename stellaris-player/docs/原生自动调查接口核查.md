## 结论与能力矩阵

当前可以复用正常调查、己方民用舰队枚举、游戏线程调度、命令合法性检查、订单取消和执行追踪。自动调查的开启及结构化查询需要补接口；撤销可以复用已有取消命令作为候选，但它是否彻底终止自动派单尚未核实。现阶段不能直接启用混合自动调查。

| 能力 | 当前实际入口 | 已核实范围 | 需要补齐 |
| --- | --- | --- | --- |
| 单次调查 | 控制器 `survey({fleet_id,system_id,queue?})`；桥 `GalaxyManager::SurveyCommand` | 原生调查命令，有合法性检查；不是自动寻找后续目标 | 继续复用作对照与回退 |
| 枚举科研船 | `get_civilian_fleets` → `GetCivilianFleetsJson` | 读取己方舰队、船型、舰船 ID、科学官及 `status` 订单文字 | 增加自动化实际状态，文字不能替代开关 |
| 开启自动调查 | 本机存在 `CAutomateFleetOrder`、`automate_fleet_order`、`AUTOMATION_SURVEY` | 自动化类型及选项存在；SDK 有订单设置与选项数组描述 | 核实 Windows 构造、设置及提交路径，再增加单舰队封装 |
| 查询自动化 | SDK `CAutomateFleetOrder` 的选项数组、survey 等设置字段 | 存在静态序列化线索，尚无已核验的运行时对象定位与读取接口 | 读取实际订单类型、完整队列、启用选项、空闲等待与当前子任务；读取失败返回未知 |
| 取消当前订单 | 桥 `cancel_fleet_orders({fleet_ids:[id]})` | IPC 已路由到游戏线程；校验归属、创建命令、IsValid、正常提交 | 控制器白名单和结果追踪尚未接入 |
| 完整撤销自动调查 | 暂无独立封装 | 取消代码注释描述 ClearOrders、CancelMovement、ClearAutoMoveTarget；不能单凭注释证明不再自动派单 | 核对当前 Execute 路径及自动化存续位置，必要时增加显式禁用；回读并观察后续状态 |
| 设置默认自动化 | SDK `CSetFleetAutomationDefaultCommand` | 载荷为 country 与 fleet_automation_group | 不是单艘科研船开关，不用它代替首个试点 |

## 可以直接复用的代码

当前桥源码在工作区 `.local/research/stellaris-mcp-native`，以下位置均相对于该目录。

- `stellaris_bridge/src/ipc_server.cpp`：`cancel_fleet_orders`、`survey`、`get_civilian_fleets` 均有现成路由，操作通过 `TaskQueue` 执行。
- `stellaris_bridge/src/galaxy_manager.cpp`：`SurveyCommand` 使用 `survey_planet_order`；`CancelFleetOrders` 使用 `fleet_cancel_orders`，并验证每个目标为己方舰队。
- `stellaris_bridge/src/outliner_manager.cpp`：`GetCivilianFleetsJson` 枚举己方民用舰队；`fleet_access.cpp` 的 `OrdersText` 提供订单文字。
- `stellaris_bridge/include/command_builder.hpp`：复用现有正常命令构造与合法性检查，不通过任意函数调用或键鼠点击开启自动化。
- 控制器 `src/native-game.mjs`、`gestalt-tasks.mjs`、`order-tracker.mjs`：复用快照、身份检查、去重、在途对账和完成跟踪；新增控制权检查必须进入相同写入口。

桥已经具备取消 RPC，不等于大肥鱼已经可以调用。当前 `ORDER_FIELDS` 中没有 `cancel_fleet_orders`，也没有自动调查启停指令。

## 开启和查询路径的证据边界

生成 SDK 中的 `CAutomateFleetOrder` 描述了 `enabled_options` 以及 survey、anomalies、astral_rifts、digsites、special_projects 等设置。多个设置共用位置并带有 `positional` 标记，不能把每项当作独立布尔字段直接写入，也不能用 Linux 字段描述替代 Windows 当前版本的布局验证。

SDK 有 `queue_fleet_order_command`，可作为提交自动化订单的研究候选；当前还没有完成其内嵌订单所有权、构造、销毁与执行路径验证。不得仅凭命令名称填充指针后派发。

本机 EXE SHA256 为 `400df27c82ddc845aa9dce79bd468d81f18f060d299cd263e3afa93aef4f7a83`。只读字符串搜索找到：

| 字符串 | EXE 文件偏移 |
| --- | --- |
| `CAutomateFleetOrder` | `0x28bc9a4` |
| `automate_fleet_order` | `0x2310038` |
| `AUTOMATION_SURVEY` | `0x23f7e10` |
| `settings_survey` | `0x23266b0` |

这些是存在性证据，文件偏移不是可调用地址，不代表指令执行已经通过。

原版 `common/scripted_actions/99_README_SCRIPTED_ACTIONS.txt` 明确说明，`has_automation_setting` 只在自动化目标选择上下文中有意义，其他上下文的临时设置集合为空；不能把事件或普通查询中返回 false 当成该舰队未启用自动化。应通过真实运行时对象读取配置。

原版 `common/defines/00_defines.txt` 设有 `AUTOMATE_FLEET_SEARCH_COOLDOWN_DAYS = 30`：自动化舰队找不到工作后可能等待再搜索。因此暂时空闲不能证明自动化关闭，暂时没有新订单也不能单独证明撤销成功。

## 社区实现哪些可以借鉴

本地 OGAS 的 `src/iag/stellaris/execution/packet/fleet_operation_commands.py` 已有 `build_ship_automation_record`，构造 `8f32` 自动化配置，并分别列出 survey、explore、anomalies 等选项。

但该构造器固定写入 `automation_enabled=1`，选项验证拒绝空列表。它没有提供可直接复用的关闭语义。该项目的历史协议与当前 Windows 原生命令后端也不能直接互换。可参考其选项白名单和逐舰队授权设计；不复制历史封包到当前会话，不将 GPL 实现直接并入 MIT 桥。

第一版只授权调查。explore 是否为当前版本必需前提，需要单独核实；异常、考古、裂隙和特殊项目不随调查一起默认开启。现有证据也没有证明自动调查能限制到大肥鱼指定的区域，不能先承诺严格遵守战略路线。

## 第二阶段的最小接口清单

以下为建议接口名称，尚未实现或暴露给模型。

| 建议接口 | 必须做到的事情 |
| --- | --- |
| `get_fleet_automation({fleet_id})` | 核实完整 ID、己方归属、科研船类型；返回实际启用状态、选项、自动化订单与子任务，未知字段明确标记；不能只返回已请求的配置 |
| `set_survey_automation({fleet_id,enabled:true})` | 从已核验的正常引擎路径开启；只允许已验证的调查选项；检查现有订单与控制权，提交后回读 |
| `set_survey_automation({fleet_id,enabled:false})` | 根据验证结果复用取消命令或专用关闭命令；重复关闭可安全处理；确认无后续自动派单后交回控制权 |

实施顺序：先补查询，确认能定位真实自动化对象；再补开启的构造与提交；最后核实撤销并接入控制权交接。取消接口返回成功只表示提交，不记录为撤销完成。没有订单时原生 IsValid 可能拒绝取消，应通过实际已关闭状态处理幂等，不能吞掉所有失败。

运行时验证包含：己方单艘科研船、ID 0、已销毁或失效 ID、无科学官、MIA、交战、原有手动订单、无可用目标、旧代次回复及停止后迟到命令。原生拒绝原因应保留，不用强制派发绕过。

## 首个动态试验方案

由用户手动载入适合调查的独立非铁人存档，所有后续控制通过正常原生接口执行。记录游戏版本、世界、舰队完整 ID、科学官、初始订单和自动化配置，保留初始存档。

1. 查询确认初始状态；选一艘己方科研船，只开启已核验的调查选项。
2. 回读自动化配置与订单，确认至少完成一个调查目标，并衔接到后续自动工作；同时观察另一项已安排的建设或生产。
3. 在活动状态撤销；另测开启但空闲等待时撤销。核对启用状态及订单，不用短暂无动作判定成功。
4. 确认收权后下达一条正常手动调查或移动命令，观察是否被原自动化覆盖。保留超过一次适用搜索冷却的观察，并结合配置回读判断。
5. 分别演练重复关闭、停止控制器、人工暂停及桥断线。无法回读时记录控制权未知，不宣称原生 AI 已停。

本轮未执行上述动态试验。第一阶段中的源码盘点与第二阶段缺口清单已形成；第一阶段全量效率基线、其他自动化领域和运行验证不因此视为完成。
