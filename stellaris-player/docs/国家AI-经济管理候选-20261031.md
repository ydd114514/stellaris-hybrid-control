## 已实现的候选

原生源码版本标为 `cyberfish-0.6.17-country-ai-economy-wip`，尚未加入加载白名单，不能当作交付版本。r2 的固定 DLL 和源码快照未改，现有客户端仍选择 r2。

- `change_job_priority_command` 的实际作用是设置 CPopJob 劳动力上限。SDK、Execute 和 IsValid 已交叉核实：country +20、完整 job ref +24、signed 原始定点 amount +28；引擎把负值归零并把上限夹到岗位最大容量。本桥不替 AI 选择岗位或数量。
- `set_colony_type_command`：完整 colony ref +20、country +24、designation 对象 +28。原生普通路径校验控制归属；候选桥更严格限定为本国拥有的普通殖民地，核对完整引用、行星与殖民地双向关系和本国 owned_planets 成员。
- 两类只在新的后端 `economy` 策略开放；旧科研/建设策略默认不开放。高层客户端尚未开放该策略，避免旧桥或未验收功能被模型误用。
- 两类命令复用正常原生生产、会话提交、Clone、Execute 和释放链，新增执行与 Clone 入口。共享 size=0x30 删除析构与原科研类相同，不重复安装钩子。
- 自然 Execute 入口与返回时直接读取实际岗位上限或殖民地专精，绑定世界代次、完整 job/colony ref，不调用完整 AI 更新作查询。
- 新经济效果校验只接受本国、完整前后回读、符合引擎夹取语义且真正改变、生命周期已排空的结果。未知、未执行、仅入队、保持原值、引用错配和未知专精重置均不算正证据。原始整数用字符串保存，避免精度与单位猜测。

离线证据：Release 编译通过；原生回执/准入/排空 3 项测试通过；新增经济效果 3 项测试通过；14 个观察/Execute/Clone 入口字节与固定 EXE 匹配。真实游戏中的岗位与专精效果尚未验收。

## 本轮继续实现：生产、关键目标保护与候选客户端

- 已从原生工厂 `AB5AC0`、独立序列化器 `B05A10` 与 GetToken 交叉核实普通 `CBuildableShip`（虚表 `23A39D8`、token `3DFB`）；殖民船沿用 SDK 虚表 `23C47E0`、token `3DFD`。船上 implementation 的完整设计引用为 buildable +538，船坞 orbitable 位于 +540/+544/+548；没有把后面的 upgrade ref 当 owner。
- 新后端策略 `economy_and_ship_production` 让原生 AI 自己选择普通船与殖民船生产；只允许 owner-type-zero 设计、普通静态星基船坞、与目标匹配的完整队列引用及本国付款队列。其他工厂分支、联邦/共同体船和移动载体队列未放行，不从脚本选择设计。
- 自然 Execute 入口/返回读取实际队列所有项目的完整 ID、队列反向引用、付款国及船型/设计/船坞。新证据校验要求独立新增且唯一的匹配项目、生命周期已排空，旧项目、未知回读和未释放 Clone 不算。该证据只证明“已排产”，不声称舰船已完工。
- `protected_targets` 支持 jobs、colonies、shipyards，每类最多256个本国完整引用；原生侧在暂停、AI关闭、同世界条件下整批验证。单个岗位可保护上限；殖民地保护岗位上限与专精；船坞保护新增生产。保护不会阻止已在队列中的项目完工，也不等于保护整个殖民地的所有建设。目标在一个委派周期内不可变，通过原生 AddAI 和已识别本国 Post 两处拦截覆盖，状态有专门阻止计数。
- 原生 lease prepare 传递并回读保护列表。高层控制类新增仅供候选联调的显式开关，要求候选完整版本及所有能力标记；先持久化已取得的代次，再核对真实范围/保护读回，一致才开启。约束丢失会收回已取得的代次；接管/交还保留同世界策略和保护。**现有 NativeGame、MCP、加载器及 DSH 默认仍用 r2，未开放候选入口给普通模型。**
- 新增生产证据、约束参数、能力协商与保护丢失收权测试；本批定向16项、现有控制器回归147项、原生3项通过，Release 编译通过。固定 EXE 的工厂/Token/序列化交叉检查见 `ship-production-layout-preflight.json`。
- 内部计划维护仍在调查：虚表 slot8 是 IsValid、slot9 才是 Execute；文件已按两类分别保存。`ai_remove_diplo_action` Execute 经 `B7E9F0` 操作 AI 自身集合；`ai_add_strategy` 经 AI 虚调用，战况刷新也存在下游调用。尚未取得完整副作用边界，均未因此放行，不把名称当作无害证明。
