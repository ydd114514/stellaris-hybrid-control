# 群星实时原生接口验证

2026-10-27更新：主玩家已在 `src/native-game.mjs` 通过社区MIT原生桥运行；这里的GPL工具负责精确进程身份、科研舰船映射和只读诊断。战争状态已转入游戏线程内的原生查询；`war_state.py` 等保留作交叉核对。新增弹窗、内阁数据库和舰队容量探针均只读，不自行点击或派发游戏指令。

下方为10月26日最初只读验证阶段的记录，不代表当前主控制器进度。

2026-10-26：主路线转为结构化实时状态 + 正常引擎命令，DSH/MCP 提供模型工具宿主；截图只作为辅助。这里是验证工具，尚非可用的自动玩家。

`stellaris_memory_probe.py` 只使用进程查询、模块枚举与 `ReadProcessMemory`。精确校验游戏文件 SHA-256 和五个运行中函数锚点，再按指定舰队 ID 查询数据库与位置。它不注入、不写内存、不发键鼠、不提交命令。

当前舰队 ID 由已有的己方存档摘要提供。**存档只能提供候选 ID，不能证明当前打开的是同一个世界，也不能证明舰队仍属于玩家。** 输出明确标注 `worldAndOwnershipVerified: false`，不会接入自动操作。位置是查询时从运行中游戏读取的，不是存档位置；读取并非游戏线程内的原子快照。

版本指纹、PDX 数据库布局、坐标虚表和系统 ID 位置参考 [V2t-Nostalgia/OGAS](https://github.com/V2t-Nostalgia/OGAS)，固定提交 `0c402a226c835d3d31eefbe2a168283517549373`。该目录采用 GPL-3.0-only（见 LICENSE），与原 MIT 键鼠原型分开。未复制其他版本的订单偏移。

下一步必须先确认当前世界/本地玩家身份、实时归属与可见范围，再在游戏线程内通过原生命令的 `IsValid` 和正常会话队列验证一次舰队移动，并回读精确目标。`posted`、无崩溃和 DLL 加载成功均不能当成操作完成。
